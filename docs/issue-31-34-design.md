# Issue 31-34 修复与实施设计

日期：2026-09-07

状态：Issue 31、32、33 本次实施；Issue 34 完成设计，暂不实现。

## 1. 范围与目标

本设计覆盖 GitHub Issue 31-34：

| Issue | 类型 | 本次范围 |
| --- | --- | --- |
| 31 | Bug | 修复等宽字体下打乱文本显示不完整或被裁切 |
| 32 | Bug | 修复分组管理中的 WCA 打乱名称索引偏移 |
| 33 | Bug | 修复深色模式下分段成绩列表的硬编码颜色 |
| 34 | 功能增强 | 在顶部打乱选择弹窗中增加成绩分组快捷切换设计 |

约束：不改变打乱分类的持久化编码，不修改成绩数据库结构，不改变蓝牙协议和计时状态机。Issue 34 只增加进入成绩分组切换的 UI 入口，不把成绩分组和打乱分类合并成同一类数据。

## 2. 根因确认

### Issue 31

`tv_scramble` 在布局中是 `wrap_content`，但 `MainActivity` 在初始化和配置变化时通过 `setHeight` 把它固定为计时页上半区域的高度。这个固定区域和居中位置属于现有布局语义，不能为了修复遮挡而改成按内容收缩。等宽字体使每行可容纳的字符减少，长打乱产生更多换行；自动字号的最小值和错误的字号单位又限制了缩放效果，最终文本会在固定高度内被裁切。

### Issue 32

成绩分组保存的是原始 `scrambleIdx`。WCA 的原始子索引和资源数组展示索引之间存在一位偏移，计时页已经在显示前修正，但分组管理直接调用 `StringUtils.getScrambleName`，没有执行同一转换，因此六阶会显示成七阶。

### Issue 33

当前成绩列表使用 `TimesAdapter`。普通成绩路径使用主题资源，分段成绩路径却直接使用白色背景和灰色文字。深色主题的背景和文字分别是黑色和白色，因此只有开启分段计时时颜色异常。`ResultAdapter` 是未接入主页面的旧 RecyclerView 路径，本次不扩大修复范围。

## 3. 实施方案

### 3.1 Issue 31：保持位置并修正打乱文本缩放

- 保留 `tv_scramble` 原有固定高度和 `gravity="center"`，确保打乱文本继续位于计时页上半区域的原位置。
- 自动字号统一使用 `TypedValue.COMPLEX_UNIT_SP`，最小字号设为 `8sp`，保留用户设置的字号作为最大字号，在固定区域内优先缩小文本以避免遮挡。
- 初始化和配置变化继续使用原有高度计算，避免旋转屏幕后位置发生变化。
- 不引入滚动手势。计时器视图当前覆盖整个计时区域并处理起停表和手势，直接给打乱文本增加滚动会与计时交互冲突。

### 3.2 Issue 32：统一原始索引到展示索引的转换

- 在 `StringUtils.getScrambleName` 内集中处理 WCA 原始子索引转换。
- 移除调用方的重复修正，让计时页和分组管理都传入原始 `scrambleIdx` 的分解结果。
- 保持数据库、偏好设置、成绩记录和打乱生成继续使用原始索引，不把展示位置写回业务数据。

### 3.3 Issue 33：分段成绩跟随主题

- `TimesAdapter` 的分段平均行和分段成绩单元格统一使用 `R.drawable.item_background` 与 `R.color.colorText`。
- 保留最佳、最慢等统计颜色，它们属于应用设置的语义颜色，不属于深浅主题背景色。
- 本次不修改未接入的 `ResultAdapter`，避免扩大当前成绩列表路径的变更面。

### 3.4 Issue 34：打乱弹窗增加成绩分组列

顶部打乱弹窗保留现有两列，并增加第三列：

1. 打乱大组
2. 打乱子项
3. 成绩分组

第三列复用 `TextAdapter` 和 `list_item.xml` 的现有选中样式，数据来源为 `sessionManager.getSessionNames()`，选中位置使用当前 `sessionIdx`。点击后设置目标 `sessionIdx`，调用现有 `changeSession()`，然后关闭弹窗。

`changeSession()` 必须继续负责成绩刷新、分段计时配置、平均值、统计标签和当前打乱同步，不能在弹窗监听器中复制这段逻辑。弹窗关闭是必要的，因为切换成绩分组可能根据该分组保存的项目改变当前打乱，继续保留旧的两列选中状态会造成误导。

布局上继续沿用现有背景、行高、勾选图标和分隔线。当前弹窗固定宽度为 `300dp`，增加第三列后需要改为按屏幕宽度约束的弹窗宽度，避免分组名称被过度压缩；不通过缩小字号解决宽度问题。

## 5. 验收标准

### 已实施的前三项

- Issue 31：等宽字体约 `20sp` 时反复切换普通三阶、六阶和长打乱，打乱文本不出现字形裁切；旋转屏幕后仍按当前屏幕尺寸布局。
- Issue 32：WCA 六阶、七阶以及后续 WCA 项目在计时页和分组管理中显示一致，保存的原始项目值不改变。
- Issue 33：深色模式下普通成绩和分段成绩都使用黑色背景、白色文字；最佳、最慢颜色仍保持原有语义。

### Issue 34 后续实现

- 顶部打乱按钮弹窗能同时看到三列，当前打乱大组、子项和成绩分组均有正确选中状态。
- 点击成绩分组后，成绩列表、平均值、分段设置、统计和当前打乱与从成绩列表入口切换时一致。
- 长分组名称在常见手机宽度下不发生布局溢出；弹窗关闭后重新打开，三列状态与当前业务状态一致。
