# Issue 34 设计：打乱弹窗快捷切换成绩分组

日期：2026-09-07

状态：设计完成，功能尚未实现。

## 背景

当前成绩分组切换需要先进入成绩列表页面，再通过成绩分组入口选择目标分组。计时页顶部的打乱按钮已经有打乱大组和打乱子项选择弹窗，适合在同一入口增加成绩分组快捷切换。

## 目标与边界

目标是在不改变成绩分组数据结构和现有切换语义的前提下，让用户可以从顶部打乱弹窗直接切换成绩分组。

不修改成绩数据库结构，不改变 `sessionIdx` 的现有索引语义，不把成绩分组混入 `scrambleIdx`，也不影响蓝牙协议、计时状态机和成绩保存流程。

## 现有实现

- `MainActivity` 的 `bt_scramble` 点击逻辑打开 `popup_window`。
- `popup_window.xml` 当前包含 `list1` 和 `list2` 两个 `ListView`，分别显示打乱大组和打乱子项。
- `TextAdapter` 和 `list_item.xml` 已提供现有选中背景、勾选图标、行高和分隔线样式。
- 成绩分组切换由 `changeSession()` 统一处理，负责刷新成绩、分段计时配置、平均值、统计标签和当前打乱。

## 方案

在现有弹窗中增加第三列，排列如下：

1. 打乱大组
2. 打乱子项
3. 成绩分组

第三列使用 `sessionManager.getSessionNames()` 作为数据源，使用当前 `sessionIdx` 标记选中项。点击成绩分组后设置目标 `sessionIdx`，调用现有 `changeSession()`，然后关闭弹窗。

成绩分组点击逻辑不复制 `changeSession()` 内部的刷新流程。这样可以保证从顶部弹窗切换和从成绩列表切换拥有相同的成绩、统计和打乱同步行为。

## 状态同步

成绩分组可能保存了自己的打乱项目。切换分组时，`changeSession()` 可能同步更新当前打乱，因此选择成绩分组后应立即关闭弹窗，避免弹窗中的打乱列仍显示切换前的选中状态。

重新打开弹窗时，应根据当前的 `scrambleIdx` 和 `sessionIdx` 重新计算三列选中项。成绩分组使用 `sessionIdx`，不使用名称比较，也不把列表展示位置写入持久化数据。

## 布局与样式

第三列继续复用现有 `TextAdapter`、`list_item.xml`、弹窗背景、行高、勾选图标和分隔线。当前弹窗固定宽度为 `300dp`，增加第三列后需要改为受屏幕宽度约束的自适应宽度，避免中文成绩分组名称被过度压缩。

不通过缩小字号解决三列空间问题。分组名称较长时应保持现有文本样式，并通过弹窗宽度和列权重提供足够空间。

## 实施边界

预计涉及：

- `app/src/main/java/com/dctimer/activity/MainActivity.java`
- `app/src/main/res/layout/popup_window.xml`

不新增数据库字段，不修改 `SessionManager` 的数据模型，不改动 `SessionActivity` 的新增、删除和排序流程。

## 验收标准

- 顶部打乱按钮弹窗同时显示打乱大组、打乱子项和成绩分组三列。
- 当前三列选中状态与当前业务状态一致，成绩分组按 `sessionIdx` 正确选中。
- 点击成绩分组后，成绩列表、平均值、分段设置、统计和当前打乱与原有成绩列表入口一致。
- 切换后关闭弹窗，重新打开时三列状态正确。
- 常见手机宽度下长成绩分组名称不发生布局溢出。
- 不产生数据库迁移，不影响 BLE 和计时主链。

## 风险与回滚

主要风险是三列弹窗在窄屏设备上的可读性，以及成绩分组切换可能同步当前打乱带来的状态变化。实现应优先保持现有 `changeSession()` 语义，并通过不同屏幕宽度的手动验收确认布局。

该功能只涉及 UI 布局和已有状态入口，回滚时删除第三列布局与监听逻辑即可，不需要处理用户数据。
